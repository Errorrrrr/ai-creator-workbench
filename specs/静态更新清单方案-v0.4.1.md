# v0.4.1 静态更新清单

## 目标与边界

更新检查从 GitHub REST API 改为读取本仓库 Release 附件 `latest.json`，采用 SkillDock 的静态附件分发方式，避免占用匿名 API 每小时 60 次额度。桌面版与浏览器服务端同步修改；仍由用户手动检查、打开下载链接和安装，不增加自动安装或 Token 配置。

## 实现

- 固定入口：`https://github.com/Errorrrrr/ai-creator-workbench/releases/latest/download/latest.json`。
- 为复用现有校验，清单采用现有解析器需要的发布字段：`tag_name`、`draft`、`prerelease`、`html_url`、`body`、`published_at`、`assets`。仅包含本次发布的 DMG 和 app ZIP 下载链接。`published_at` 记录清单生成时间。
- JS 和 Rust 检查链路均使用静态入口，只跟随 HTTPS 本仓库清单路径和 `release-assets.githubusercontent.com`，最多五次重定向。整体请求超时和 1 MiB 响应上限保持，安装包链接仍严格限制到本仓库对应 tag 的发布路径。
- 清单 404 表示未找到可访问的更新清单，不表示已经是最新版，不回退 API。
- 发布脚本生成清单，纳入 SHA256SUMS 与发布元数据；验证清单版本、附件链接、文件摘要与 tag/commit 一致。发布脚本上传全部四个附件、验证后才公开，预发布和旧版本不抢占 Latest。
- 应用版本统一提升至 0.4.1。0.4.0 及更早客户端仍使用旧 API，需升级一次才能切换。

## 验证与交付

运行已有 JS/Rust 测试、语法检查和桌面发布构建；同步已有测试中因 endpoint、重定向策略和附件数量改变而失效的断言，不新增测试文件或用例。额外执行临时验证脚本检查可信重定向、拒绝陌生来源、循环重定向及清单到版本状态的完整路径。

本地替换应用，确认启动和项目读取。本轮已经生成的备份保留，按用户后续指令不再额外备份旧应用。提交、推送功能分支并发布 v0.4.1；完成必要的发布结果核对后结束，不设置持续监听。Git 推送、GitHub Release 与本机验证分别记录。

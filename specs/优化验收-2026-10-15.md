# 候选稿、差异审阅与写作空间优化

日期：2026-10-15。源码版本：0.5.0。本地实现、自动检查、浏览器回归及隔离 macOS 原生应用验收完成，保持既有暖纸、墨色、琥珀配色及写作字体。Tag、公开发布与安装记录以交付回执及 [GitHub Releases](https://github.com/Errorrrrr/ai-creator-workbench/releases) 的实际记录和附件为准。

## 已实现

- 待审稿按项目、文档和正文／大纲／引用页签保存；保留请求、实际发送消息、引用、原文基线、完成状态和时间。重试新增一稿，停止／中断保留部分内容，切换和重载可恢复。每项目最多 100 稿，不自动删除旧稿；沿用全库容量限制和保存失败提示。
- 文字、讨论、项目计划和分镜候选均随项目保存与备份。手动修改分镜 JSON 同步到待审稿；文字／计划／分镜采纳在同次保存移除对应来源稿，失败保留或回滚，不误删其他候选。
- 文字候选及项目计划的文档修改提供逐行增删高亮、变更统计、前后跳转和完整前后文本。空白、中文、CRLF 与末行换行保持可识别；长文本采用有界比较和展示回退，提示回退范围。项目计划仍整批校验与采纳。
- 创作目标、步骤说明和助手上下文可折叠；压缩常驻头部、合并纸面标题。助手输入与上下文区独立滚动，给候选和差异留出阅读空间；保留窄屏触控尺寸、浅深主题和键盘焦点。
- 已合并远端 v0.4.2 的项目永久删除及关联媒体清理功能；本轮保留该功能，不将其计作三项优化的新功能或新增真实删除验收。

## 原生应用与 SQLite 实际验证

使用上述独立应用标识的 macOS debug 原生包和隔离 SQLite 数据库，连接 `127.0.0.1:43918` 的固定 Ollama 格式响应服务。操作通过真实原生应用界面完成，结果核对隔离 SQLite；没有调用真实供应商，也没有使用正式应用中的创作项目。

1. 生成两份完整文字候选，重新生成后旧稿继续保留；差异审阅显示两处修改，前后跳转可用。
2. 在预计 30 秒的慢流生成中正常关闭窗口，实际收到并保存 60 段中的 12 段，状态为 `partial`。退出后重新打开应用，三份待审稿全部恢复，原正文保持不变。
3. 选中一份完整候选替换正文，建立 v2；SQLite 核对正文已更新且只删除该来源稿，另一完整稿与部分稿继续保留。
4. 生成项目计划，原生界面展示两处修改预览，采纳后 SQLite 中正文正确、共四个版本；此时保留两份待审稿，状态分别为 `complete` 和 `partial`，已采纳计划稿已移除。
5. 最终修正版重新构建、签名并启动后，再次核对待审稿恢复；新增生成并采纳一次，播报为“已采纳并建立快照 v5”，不再含“丢弃”。最终隔离测试库保留两份待审稿、五个版本，正文与计划验收后的内容一致。

## 边界与下一步

- 本轮覆盖浏览器与隔离原生应用的候选、差异和 SQLite 正常退出恢复；没有新增真实模型、图片或视频生成验收。Debug 原生包构建与启动不等同于公开发行包安装。
- 备份导入为独立项目时保留原请求目标标识。旧项目的操作计划和分镜候选不会自动获得对新项目的执行权限，应重新生成；文字仍可审阅并由用户采纳。
- 保存仍受现有库容量限制；浏览器关闭不能保证最后一个未落盘片段，仍需观察保存状态。长期创作资料应另存备份。
- Tag、公开发布、发行附件校验及具体安装记录以交付回执和 GitHub Releases 为准；本记录不预先宣称公开发布或安装完成。其他设备与旧版本的升级组合、Developer ID 签名与公证仍需各自验证。

# 多模态实现契约与进度

日期：2026-10-12。产品范围以《多模态创作工作台产品方案》为准，本文件维护接口、逐次证据和未覆盖范围。当前 P0 文字与 P1 分镜／图片核心主路径通过；P2 按用户选择先完成通用接入框架，不代表真实视频验收或正式发布。

## 交互约定

- 项目内提供创作／分镜／素材切换；无项目时只能创建或导入。分镜和素材不填示例内容。
- 分镜支持空白新建、从当前文档 AI 拆镜、候选采纳、直接编辑、上移／下移、参考版本选择、图片与视频生成。
- 分镜保存来源文档及内容指纹；来源变化标记过期，不删除镜头或替换已选媒体。候选采纳校验基础修订号。同一计划同时改写来源正文并追加镜头时，新镜头绑定整份计划完成后的最终正文，不依赖操作排列顺序；已有镜头的来源指纹不重写。
- 素材按角色／场景／道具／风格／镜头／其他分类，版本保持不变；修改选用版本不改变既有镜头引用。
- 执行端按文字／拆镜／图片／视频分别配置。变更选择保留输入，不自动执行，不混用密钥。
- 文字默认执行端与拆镜路由不以检测失败为理由换资源。运行时检测只更新安装／可用状态，不能改写已选 CLI 的 `isActive` 或项目选择；选定资源失效时保留名称及失败原因，由用户重新选择。拆镜未单独选择时可继承项目文字选择，再继承已明确标记的全局文字默认；不从列表中自动挑选第一个可用资源。保存旧项目时也不因本次检测失败把其他资源写成新默认。
- Codex 连接可选 `planningModel` 仅记录用户明确填写的规划模型 ID，默认空白。CLI 连接既有 `model` 存放检测版本，不作为模型覆盖透传；检测不得覆盖 `planningModel`。默认通过已安装 CLI 的只读 `config/read` 读取用户有效模型配置；该元数据进程不创建线程或轮次，禁用 hooks／插件等，并在八秒内退出及清理进程组。只提取经校验的模型 ID，不复制完整配置或凭据，不继承自定义供应商；读取失败直接停止，不忽略配置后另选模型。显式覆盖优先于本机设置。文字执行仍用 `--ignore-user-config`／`--ignore-rules`，但将已解析模型以单个 `--model` 传入；图片通过 `thread/start.model` 传入并检查实际返回模型，不把 `model/list.isDefault` 的推荐模型当作用户当前配置，也不因旧目录不含已配置模型而替换或拒绝它。仅当本机未配置模型时保留 CLI 自身缺省行为。ID 最多 128 字符，以 ASCII 字母数字开头，只允许字母数字与 `._:/-`；不是任意 CLI 参数。
- “连接中心 → Codex CLI → 模型设置”仅保存，不检测权限或触发生成；设置变更使文字会话执行许可失效，后续需按既有规则确认。文字确认与媒体批量预览显示规划模型，固定媒体请求包含该值，变更须重新预览。保存失败恢复原连接设置并保留表单输入；现有任务保持原快照。规划模型不等于底层图片模型，实际图片模型没有回执时明确未知。项目／完整媒体备份仍不携带连接配置，恢复复用本机连接，而不是借备份创建新的模型设置。
- Codex 安全错误诊断沿用既有字符串返回／Job.error，不新增 IPC 字段或数据库结构。文字使用 `--json`，非成功退出保留退出码（或信号终止未知）、CLI 已报告的线程／轮次阶段及经校验的请求规划模型；只从 `error.message`／`turn.failed.error.message` 分类，不读取 item 正文、工具输出或未知字段。命令行选项、字段类型、未知字段、缺少字段、未知方法和请求参数分开提示；不明错误事件不覆盖已有明确诊断，无阶段事件时明确未知，CLI 阶段不等于远端执行或计费证据。成功仍只采纳 `--output-last-message` 的最终答复，不将 JSONL 事件流当作正文。图片协议错误保留初始化／设置／账号／线程／轮次阶段，JSON-RPC 参数错误优先于消息中的模型字段，按 `codexErrorInfo` 白名单分类，HTTP 状态只保留 100–599 的整数。只有明确的模型拒绝表述才标为模型相关拒绝，单独出现 `model` 不等于账号权限不足。原始事件／消息、additionalDetails、stderr、提示词和路径不输出、不持久化；没有可分类信息时明确未知。请求规划模型不代表底层图片模型或账号可用性。历史失败记录不重写，不能补出此前已丢失的错误。
- 全局默认与项目覆盖分开：连接中心新增文字／图片／视频全局默认选择，文字沿用 `isActive`，媒体连接新增可缺省的 `defaultFor` 数组（仅 `image`／`video`），仍由既有全局连接设置保存，不新增数据库 schema。未配置默认允许保留为空，不自动将列表首项设为默认；同能力出现多个默认时停止并提示重新选择。
- 统一路由：文字为项目文字 → 全局文字；拆镜为项目拆镜 → 项目文字 → 全局文字；图片／视频为项目对应步骤 → 同能力全局默认。只有未配置上一层时才继承；被选资源缺失或能力不匹配直接报错，不能跨能力或跳过失效选择。助手、步骤详情、镜头生成与批量计划使用同一解析结果。
- 修改全局默认不改写任何项目的显式选择；助手和“用于当前项目文字”只修改当前项目文字覆盖，无项目时卡片明确提供“设为全局文字默认”。项目选择空项表示继承，并展示实际继承名称；更换或清空资源不生成内容，不传输上下文或读取凭据，保存失败显示失败并保留待保存选择。
- 连接表单仅在项目库保存成功后关闭并显示成功。保存中禁用字段、检测、重复提交与关闭操作，显示忙碌状态；失败保留表单和输入，显示尚未保存及重试／备份建议，不用成功提示覆盖保存错误。检测中的旧结果不得解除保存锁或覆盖错误反馈。
- 生成按钮明确提交范围；批量任务一次确认。生成完成进入候选，审核通过由用户明确选择。取消停止后续步骤，远端不可取消时保留句柄并说明可能计费。
- 分镜直接选用与项目计划采用相同的视频审核规则：更换选用视频版本清空审核标识，切回旧版本也需重新审核；重复选用当前同一版本不清空。编辑其他镜头字段不自动修改视频审核标识。
- 单镜提交先校验资源、镜头和引用并冻结签名，再保存当前项目；预检失败不为了生成而保存项目、读取凭据或创建任务。保存后与读取凭据后分别核对原始签名，输入或执行端改变时拒绝提交，要求重新核对。
- 列表覆盖加载、空态、错误和有数据；编辑保存前校验，失败保留输入。所有操作有文字或可访问名称，排序提供非拖动替代。
- 文字发送范围可展开实际片段与完整消息，支持正文／选区开关、逐项移除和恢复默认。`@` 选择器只列当前项目对象，明确添加文档、镜头或固定素材版本说明；当前文字接口不支持视觉输入时只发送素材说明，不声称发送图片字节。发送前冻结完整消息；候选区保留实际已提交快照，之后编辑引用只影响下一次请求。引用选择仅属当前会话，切换项目清空。
- 批量图片／视频先选镜头、能力与执行端，再预览每项固定输入、参考版本、数量及费用未知提示，一次确认后创建任务。计划变更需重新预览，不在已确认范围外补生成；取消批次停止未开始任务，已交付产物保留，不承诺远端停止计费。
- 原生素材／项目包共用官方 Tauri dialog 选择器：后端绑定主窗口，同一应用只允许一个选择器等待；取消不导入，由回调持有生命周期锁直到原生面板结束。仅提出关闭但保存失败、窗口仍保留时，不提前终止选择器；实际退出后不留独立选择器进程，不向前端开放任意文件系统路径或通用文件面板权限。

### 创作步骤导航

- 项目内固定显示当前路径、步骤选择及上／下一步。文字路径为灵感、简报、大纲、正文、导出；剧本路径补充世界、人物、剧本及可选分镜／图片／视频；分镜路径从已有文本、正式参考、拆镜开始。可任意跳步和返回，不将序号当作完成率，不自动生成、清空内容或创建媒体任务。
- 步骤详情展示可用输入、所选执行端与输出位置；实际发送内容仍以助手／媒体计划预览为准。资源待检测、缺失或不可用如实说明，图片和视频不回退到文字连接；可进入连接中心或知识库配置。导出无需 AI 资源。
- 文字正文使用 `draft` 文档，仅在用户首次进入该步骤时创建空白结构；已有文档不覆盖，旧项目保持可读，正文纳入目录、上下文与导出。剧本步骤打开已有分集／分场，尚无分集时打开创建表单，不自动建立多集骨架。
- 切换前保存当前输入，保存失败停留并保留原内容；新正文先成功保存后替换内存。切换项目重新定位步骤；通过目录或视图自由导航时同步当前位置。步骤选中态是会话导航，不新增持久化 schema 或伪造完成状态。
- 375px 和横屏下保留文字标签、至少 44px 操作目标及真实滚动；详情默认折叠，展开不遮住正文和键盘焦点。没有项目时隐藏步骤栏；知识库、连接中心等全局视图不挤占内容区域。

## 项目修改计划（受控文档、镜头及媒体操作）

助手请求分为讨论、文字候选和项目计划。讨论无采纳写入入口；文字候选沿用原有插入／替换／追加；项目计划只生成 JSON，不直接修改项目。支持 `write_document`、`append_shots`、`update_shot`、`select_shot_media`、`prepare_media_batch`，补充只读 `query_media_tasks`；完整主路径继续按产品方案实现，不能将这组操作视为全部 Agent 能力完成。

- 计划格式为 `{version: 1, summary, operations}`，每项操作必须使用 `tool` 字符串指定操作名，参数直接放在同一对象中，不接受 `type`／`name` 别名或 `arguments`／`parameters` 嵌套参数。模型指令给出完整 JSON 格式示例，缺少 `tool` 时准确说明格式错误并拒绝执行。最多 20 项，原始 JSON 最多 100000 字符；拒绝未知操作／字段及原型污染字段。空操作仅呈现无法执行的原因，不开放采纳。不接收 Shell、任意路径、凭据或供应商命令。
- `write_document` 参数为 `documentId, tabName, mode, content`；`tabName` 仅 `script`／`outline`／`references`，`mode` 仅 `replace`／`append`，单项内容最多 20000 字符。目标必须属于当前发送上下文，写入前保留旧快照并建立新版本。历史达到 50 条上限时也须保留采纳前内容；仅复用最新且同标签、同内容的快照，不能因即将被裁剪的旧记录含有相同内容而跳过采纳前快照。
- `append_shots` 参数为 `sourceDocumentId, shots`；最多新增 20 个，项目总数不超过 120。只追加，不清空已有镜头；镜头 ID 由应用创建，来源固定到采纳时的正文。`update_shot` 参数为 `shotId, patch`，只允许标题、画面、对白、动作、运镜、时长、起止状态和衔接方式，不允许模型修改媒体引用、审核状态或伪造文件。
- 可修改目标只来自当前文档及已发送上游／主动引用对象；发送的目标清单仅包含标识、标题与允许的视图，不自动附带其他正文。完整文字请求仍限定 24000 字符，计划指令和目标清单计入预算；目标过多要求减少引用，不静默扩权。
- 审阅弹窗允许修正 JSON，展示所有改动前后内容。输入变化使旧预览失效；计划目标改变或切换项目后拒绝采纳，不覆盖后续编辑。文档与分镜在同一次项目保存中提交；保存成功前不替换当前内存内容，失败保留原内容与计划供重试。
- 可以审阅粘贴的已有计划，但仍只允许当前明确上下文中的对象。空白输入不预填示例计划。预览和采纳仅操作本地项目，不隐含图片／视频生成或额外模型调用。
- `select_shot_media` 参数为 `shotId, kind, versionId`；`kind` 仅 `image`／`video`。镜头及媒体版本必须都在本次明确引用中，媒体还必须属于当前项目、种类匹配且保持原版本。预览展示真实版本说明及已有预览；采纳前通过 `media_verify_versions` 核验文件，不接受模型自造版本或路径。更换视频选用版本清空当前审核标识；选择素材不代表视觉一致性审核通过。
- `prepare_media_batch` 参数为 `capability, shotIds`；能力仅 `image`／`video`，1–20 个不重复的已引用镜头，同一计划最多一项。此操作只打开既有批量计划并带入选择，不调用供应商或读取密钥；用户可修改／返回，预览后才确认实际生成。与本地编辑混合时先审阅并保存编辑，再核对真实媒体输入；准备计划与授权生成是不同阶段，不逐镜头确认。
- 准备操作单独使用时不创建文档版本或写入无变化项目。修改 JSON、目标／素材失效、目标后续编辑或项目切换时，旧审阅不可继续；本地保存或文件核验失败保留输入，不打开生成计划。未加载成功的媒体不能进入允许版本清单；无素材、无桌面执行环境或资源缺失时明确说明，不提供模拟素材／任务。
- `query_media_tasks` 参数为 `shotIds`，1–20 个不重复的本次明确引用镜头，每份计划最多一项。预览时只读查询当前项目这些镜头的本地持久化任务，按更新时间倒序最多返回 20 项及截断标记；返回任务标识、目标镜头、能力、阶段、创建／更新时间和历史恢复标记，不返回输入正文、远端句柄、路径、地址或凭据。不查询供应商、不执行恢复、不提交生成，不以本地阶段声称远端实时状态。
- 纯查询预览显示读取中、无任务、摘要或错误，完成后无需采纳或保存；查询与编辑混合时，查询结果仅供参考，只有编辑／准备操作可以继续采纳。读取失败保留 JSON，项目／镜头或输入改变后拒绝沿用旧结果；重开或重新预览取得新快照，不把正常任务状态变化当作文档修改冲突。浏览器不伪造桌面查询结果。

## 数据约定

旧项目 `schemaVersion: 2` 保持可读，新字段均可缺省为空。项目 `workflow` 保存流程预设与各步骤执行端；`storyboard` 保存修订号、有序镜头和候选。

镜头包含 `id`、`title`、`sourceDocumentId`、`sourceFingerprint`、`visual`、`dialogue`、`action`、`camera`、`duration`、`entryState`、`exitState`、`transition`（`cut`／`continuous`）、`references`（`versionId`＋用途）、`selectedImageVersionId`、`selectedVideoVersionId`、`reviewedVideoVersionId`，以及 `aspectRatio`、`imageSize`、`imageQuality`、`videoMode`。文件字节不写入项目 JSON。

媒体由 Rust 独立 SQLite 表管理，关联实际项目 ID：

- Asset：`id`、`projectId`、`name`、`role`（`character`／`scene`／`prop`／`style`／`shot`／`other`）、`kind`（`image`／`video`）、`versions`、`selectedVersionId`、时间。
- MediaVersion：`id`、`fileId`、`name`、`mimeType`、`bytes`、可获取的尺寸／时长、`createdAt`、`metadata`。`fileId` 是内部标识，不是任意文件路径。
- Job：`id`、`projectId`、`targetId`、`capability`、`status`、时间、`remoteId`、`assetId`、`error`、`request` 输入快照、`restored`；批量任务另含可缺省的 `batchId`、`batchIndex`（从 0 开始的计划顺序）。快照不得包含密钥；从项目包恢复的历史任务只供追溯，不复用原远端句柄或执行许可，批次标识重新映射。

任务状态：`queued`、`submitting`、`running`、`downloading`、`completed`、`failed`、`cancelled`、`submission_unknown`。远端完成、本地收录、人工审核是不同事实。

没有远端句柄的 `submission_unknown` 任务尝试本地恢复时，未找到可验证产物不能证明原提交失败；继续保留未知状态、可能计费及不会自动重提的提示。只有取得并核验已有结果才进入收录完成，不因一次恢复失败改为普通 `failed`。

单项及批次取消先锁定运行登记再读取任务；存在活动令牌时仅发送取消信号，由工作线程持久化最终结果。非活动任务的已完成、失败、已取消及提交未知终态保持原样；没有远端句柄的 API 提交中任务停止等待后保留为 `submission_unknown`，不隐藏可能接受并计费的风险。

恢复入口同样在运行登记锁内读取最新任务；原任务已完成则直接返回原结果，不用锁前旧快照覆盖素材关联或启动多余恢复。活动任务拒绝重复恢复，历史恢复记录仍不可执行；已有远端句柄和提交未知语义不变。

## Tauri 命令（参数及返回字段使用 camelCase）

| 命令 | 参数 | 返回 |

### 通用媒体适配器契约

`media_adapter_catalog()` 为无参数、只读 IPC，不访问账号、密钥或供应商。响应：`{schemaVersion: 1, adapters: Descriptor[], cancelScope: "local-only", verification: "implementation-only"}`。Descriptor 包含 `id`、`name`、`transport`（`api`／`cli`）、`capability`（`image`／`video`）、`driverId`（API 为 null）、`modes`、`referenceRoles`、`maxReferences`、`remoteQuery`、`remoteCancel`、`recovery`、`parameterNotes`；这些字段只描述实现范围，不是实时账号能力探测。

后端 `media_adapters.rs` 的固定注册表以 adapter ID 精确选择，并同时核对 transport、driverId 和 capability。`MediaAdapter` 提供 `descriptor`、`validate`、`submit` 和 `recover`；`submit` 完成适配器自己的提交／查询／下载协议，`recover` 只能收录已知文件或查询既有句柄，禁止再次提交。公共任务层继续负责队列、取消令牌、持久化、批次、原子检查点和解码／收录；当前所有取消均为本地等待取消，不声称提供远端撤单。

已迁入三项实现：`codex-native-image`（CLI/codex/image，原生图片回执恢复）、`openai-images`（API/image，本地响应或文件恢复）、`veo`（API/video，既有 operation 或文件恢复）。未知协议、错配驱动／能力、未支持模式或参考用途在登记／执行前拒绝，不自动转换成 Veo／Images。前端从目录生成协议选项与能力说明；目录读取失败停止媒体提交。旧连接缺失协议时只继承历史映射，明确的未知标识保留为不可用；新增 API 连接要求明确选择协议。

新增 API／CLI 接入步骤：实现该接口及准确的模式／参考限制 → 明确认证与产物证明 → 注册固定 ID → 核验 URL／句柄／下载边界或 CLI 白名单及参数 → 验证失败不重试、恢复不生成、取消不虚报远端停止。新参数或新输入形式仍需扩展受控 Request 与界面契约，不支持任意 JSON／Shell 透传。本次不添加视频 CLI，也不先绑定新的视频供应商；具体资源另按官方协议实现与验收。

批量请求复用上述 Request；本机活动及排队任务合计最多 32 项，媒体执行并发最多 3，CLI 与文字任务共用互斥执行且可取消等待。重启不自动提交未开始任务；保留批次与输入供核对。提交预览不读取密钥、不调用生成；确认前和读取凭据后均核对计划，输入或资源改变时要求重新预览。确认调用结果不明时不自动再次提交，可先从任务中心核对同批次。费用无法可靠计算时明确未知。

自定义 `workbench-media` 协议只读取媒体库登记过的 `fileId`，支持正确 MIME 和视频 Range；前端用 `convertFileSrc(fileId, 'workbench-media')` 获取平台对应 URL。拒绝任意路径、目录穿越、越界符号链接和未登记文件。

完整项目包使用带版本的 `.acwpack` 容器，包含元数据、真实媒体与 CRC32 校验清单；CRC32 用于发现意外损坏，不提供来源认证或防篡改签名。导入先验证和重映射 ID、保存待导入记录，再发布文件，经 `library_write(mediaImportId)` 复核文件校验后原子登记独立项目。待导入数据另含只读内部恢复字段 `stageDirectory`、`sourceFiles`，仅引用应用管理目录，不接受前端任意路径；已验证暂存文件可在中断后继续发布。旧 JSON 备份仅含文字／结构，不含媒体字节。未完成导入可从入口继续，不能将已恢复历史任务当成可以自动续跑的新任务。

JSON 备份与完整项目包均保留流程预设及文字／拆镜／图片／视频的执行端 ID，不携带连接配置、密钥或执行许可。恢复后所选 ID 在本机不存在或能力不匹配时明确不可用，不悄悄改用全局默认。旧版本已清除的执行端 ID 无法从包中反推，需用户重新选择。

媒体数据库版本为 2：新增 `media_registrations` 持久化登记记录。媒体校验完成后先写记录，再原子发布文件，登记资产／文件与移除记录使用同一事务；项目读取时尝试恢复登记，校验不通过则返回 `recoveryIssues`。未来版本在执行媒体 DDL 前拒绝打开；媒体子目录禁止符号链接越界。共享文件校验实现位于 `media_integrity.rs`。

生成任务再次收录前，按项目、任务及固定产物名定位既有待登记记录，并核对镜头、能力与版本归属；优先恢复同一版本，不为同一已暂存产物另建版本。记录损坏、重复或校验失败时保留记录及文件并停止本次收录；不尝试恢复其他任务或重新生成。已恢复素材即使尚未写回 `Job.assetId`，镜头候选也可通过版本的既有 `provenance.jobId` 与本镜头任务关联展示；不自动选用、不将任务失败状态改成成功。

复用已经登记的任务产物版本时，仍须复核登记文件的项目归属、长度、MIME、真实格式，并比较其与本任务固定输出的长度及 CRC32；不能仅凭来源元数据将任务标为完成。文件缺失或变化时保留原版本与任务输出，不覆盖文件、新建版本或重新生成，待原媒体恢复后沿用原版本。

单项素材的内部登记记录增加可缺省的 `stagingFile`，只保存应用生成的暂存文件名，不接受前端路径。验证后的文件及暂存目录先同步，再保存恢复记录；最终文件尚未发布时，读取项目可核验暂存文件并继续原子发布，登记事务成功后才清理暂存引用。旧记录没有该字段时仍核验原最终文件，不能据缺失字段重启生成。完整包导入同样在保存待导入记录前同步暂存目录及其父目录，登记或发布失败不自动丢弃已验证字节；导出在返回成功前同步最终项目包所在目录。以上为实现约束，断电与原生中断恢复须另行验收。

任务检查点的 `atomic_file` 在同步临时文件并发布后，同步所在目录及父目录；API 图片响应、图片输出、远端视频句柄和 Codex 原生产物记录共用此约束。任务目录须在提交任务前同步父目录；视频流式下载另行在发布后同步输出目录及任务目录。媒体根目录创建后同步自身及应用数据目录。当前目录同步实现仅适用于 Unix，不能据此宣称 Windows 持久化已验收，也不把这些同步调用视为断电恢复测试通过。

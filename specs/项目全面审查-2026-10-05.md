## 必须优先修复的 3 项问题

### P1-01：AI 采纳保存失败会覆盖等待期间的新输入

触发：采纳候选后，保存仍在等待；用户继续输入；本次保存随后失败。回滚不检查编辑修订号，直接把文档和编辑框设回采纳前内容。隔离复现中，新写入的内容被抹掉。

定位：[app.js:1625](/Users/zxx/dev/ai-creator-workbench/src/app.js:1625)、[app.js:1634](/Users/zxx/dev/ai-creator-workbench/src/app.js:1634)。

建议：给采纳建立事务 ID、候选 ID 和编辑修订号。失败时只撤回该事务，保留后续编辑；避免旧请求修改已切换文档的编辑器。验收至少覆盖延迟保存、保存失败、连续输入、切换文档与重复点击。

### P1-02：桌面关闭窗口遗漏未保存的灵感草稿

原生关闭回调仅调用项目的 `saveImmediately()`，成功后直接 `destroy()`。灵感正文还在独立表单中，既未保存也未检查 `inspirationUI.dirty()`。浏览器的 `beforeunload` 保护不能代替主动销毁窗口前的检查。

定位：[app.js:3687](/Users/zxx/dev/ai-creator-workbench/src/app.js:3687)、[inspirations.js:13](/Users/zxx/dev/ai-creator-workbench/src/inspirations.js:13)。隔离调用原始回调得到：项目已保存、窗口已销毁、灵感仍为未保存状态；未在真实原生窗口执行该破坏性场景。

建议：统一项目正文、灵感草稿及进行中保存的退出保护，保存失败时保持窗口打开；分别验收关窗和应用退出。

### P1-03：能保存的项目可能无法备份，也无法重新导入备份

项目库采用紧凑 JSON，备份采用带缩进 JSON，并继续携带可重建的语义向量。数据库写入、桌面文件导出和备份导入却都限制为 64 MiB。

使用 1500 个片段、1024 维合成向量复现：项目库载荷约 **39.04 MiB**，备份约 **67.31 MiB**。前者可通过大小检查，后者导入实际报“备份超过 64 MiB”；桌面导出也会被上限拒绝。这里验证的是序列化与大小检查，没有向真实数据库写入大样本。

定位：[project-store.js:182](/Users/zxx/dev/ai-creator-workbench/src/project-store.js:182)、[project-store.js:189](/Users/zxx/dev/ai-creator-workbench/src/project-store.js:189)、[storage.rs:33](/Users/zxx/dev/ai-creator-workbench/src-tauri/src/storage.rs:33)、[storage.rs:73](/Users/zxx/dev/ai-creator-workbench/src-tauri/src/storage.rs:73)。

建议：备份排除可重建向量，统一存储/导出/恢复大小预算；对每个可保存样本保证备份可以恢复。容量限制实际针对全库 JSON 载荷，不等于 SQLite 文件的物理大小上限。

## 产品与工程完善项

### 数据与恢复

- **项目生命周期**：提供归档、恢复及有保护的删除入口。当前 64 MiB 是全库载荷限制，所有项目一起提交；错误提示建议“导出并归档”，界面却没有归档操作。
- **可用的灾难恢复**：SQLite 的 id=2 与 IndexedDB 的 previous 已保存上一份内部快照，但正常加载只取 current。应提供校验、导出原始数据和恢复上一份的入口；避免数据损坏后只剩报错页。
- **手写版本**：增加手动快照和覆盖前快照，明确自动快照保留策略。当前版本主要由 AI 采纳和恢复产生，不能满足纯手写用户的长期追溯需求。
- **完整备份**：补充灵感库结构化备份/恢复与全库迁移。灵感库 Markdown 导出可阅读，但不能完整恢复 ID、时间及结构；单项目 JSON 不包含独立灵感库。
- **完整 schema**：备份导入与启动加载应共用校验。例：`versionCounters` 未严格验证，字符串计数会参与拼接，产生后续无效版本。应校验类型、范围、引用关系和结构一致性，并明确迁移版本。
- **容量和性能**：每次保存都会克隆并提交整个库，包含所有项目、历史和向量；随着资料增长会增加内存及写入成本。建议按项目/文档/版本/向量分表或分记录增量保存，并展示实际占用。

### AI 与知识体验

- **桌面流式输出**：Rust API 生成固定 `stream:false`，完整返回后才显示；浏览器为流式。通过 Tauri Channel/事件推送增量，并区分连接、空闲和总时长超时。当前 120 秒总超时可能让慢模型整段结果不可见。定位：[runtime.rs:824](/Users/zxx/dev/ai-creator-workbench/src-tauri/src/runtime.rs:824)。
- **上下文可核对**：展示本次发送哪些正文、哪些上游材料、哪些知识，以及截断位置。第二个上下文开关实际总是人物文档，但文案随阶段变成“受众洞察/知识引用”等，应使标签与数据一致。
- **连续创作**：支持候选临时保存、多候选对比、继续改写及请求来源记录。当前切换文档会丢弃候选；应给出保留草稿或恢复入口，避免长生成结果无法续接。
- **知识同步预览**：已有 UI 声明 80 文件、单文件 1 MiB、累计 4 MiB 上限，但缺跳过清单。重新同步会整体替换来源，应该展示新增、修改、删除及跳过文件，避免限额造成无感资料消失。
- **语义索引覆盖率**：显示已索引/待重建片段数，清理失效缓存。用固定样例评估中文检索召回，不能仅以返回了分数判断检索质量。
- **CLI 兼容**：桌面只扫描固定安装目录，nvm、Volta 等位置可能找不到。可提供受控的路径选择和版本兼容检测；Gemini 执行属于待扩展能力。

### 使用体验、维护与发布

- “本周创作”没有按周过滤，进度按全项目内容统计；项目 stage 缺对应自动状态流转。应先修正文案，再决定是否增加计划与完成状态。
- `app.js` 约 3722 行，集中管理 UI、状态、保存、生成、导入和项目切换。建议优先拆出保存事务、AI 任务及上下文、知识生命周期，再拆 UI，降低同一异步操作跨项目修改状态的风险。
- 缺正式前端行为测试与 CI；现有 `npm run check` 只是语法检查，且未覆盖 `antigravity-protocol.mjs`。应增加端到端主路径与故障回归，Rust 增加 storage/runtime 单元及协议测试。
- README 和 `specs/交互说明.md` 有版本冲突：既写 Codex 已执行，也写仅检测；仍称独立灵感库未完成，旧交互文档仍写单项目、160 片段。应维护一份能力矩阵，标明桌面/浏览器、已实现/已实测。
- 正式分发需 Developer ID 签名、公证、安装升级验收和版本迁移测试。当前 ad-hoc 签名可用于本机开发；自动更新与 Windows 交付尚未完成。
- 文生图、视频、素材生产、多 Agent 编排、多人协作和云同步不在现有实现内。是否增加应由产品目标决定，不建议把它们排在内容保护和恢复之前。

## 安全边界审查

已有有效措施：桌面 CSP、Keychain 按连接及端点隔离、项目备份不包含连接密钥、固定 CLI 白名单和参数、临时工作目录、响应上限与取消机制、Node 桥仅监听回环地址。不同 CLI 的用户配置与工具权限边界已在确认文案中区分。

仍需加固开发服务器：[dev-server.mjs:417](/Users/zxx/dev/ai-creator-workbench/scripts/dev-server.mjs:417)、[dev-server.mjs:447](/Users/zxx/dev/ai-creator-workbench/scripts/dev-server.mjs:447) 将项目根作为静态资源目录，未限制 Host 或点文件。隔离处理器复现 `/.git/HEAD` 和未知 Host 仍返回 200。应限制静态文件白名单并校验 Host；远程利用还需要 DNS rebinding 等额外条件，本次没有进行外网攻击，也没有发现或宣称真实泄密。

另需补 IPv6 loopback 单元用例：后端用字符串比较 `::1`，与 URL 主机序列化可能不一致；建议使用 IP 类型的 `is_loopback()`。这项属于边界兼容审查，未作为本次已执行的 Rust 用例。

已排除一个表面疑点：桌面读取凭据期间取消，看起来前端缺后续 abort 检查，但 Rust 保存未注册任务的取消标记，注册时会取消该任务，因此没有将它误报为取消失效。

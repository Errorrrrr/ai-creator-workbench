# AI 创作工作台

面向灵感、故事设定、短剧与漫剧剧本的本地优先写作工具。支持多项目、独立灵感库、知识检索和可切换的 AI 执行端。没有配置 AI 时，仍可创建、编辑、备份和恢复内容。

工程名：`ai-creator-workbench`，当前版本：`0.3.0`。浏览器模式使用 IndexedDB，Tauri 2 桌面模式使用 SQLite。首次启动为空白工作台，新项目不预填示例正文、分集或分场。

当前分支的 P0 文字闭环和 P1 分镜／图片主路径已在 macOS 隔离桌面环境完成验收：现有 Codex CLI 生成六镜头及带固定参考的真实图片，候选明确选用、重启保存和完整项目包恢复通过。视频阶段目前按用户选择先提供通用接入框架，真实视频生成尚未验收；本轮不是正式发布。范围和逐项证据见 [多模态实施契约](specs/多模态实现契约.md)。

## 开始使用

浏览器开发模式要求 Node.js 18 或更高版本：

```bash
npm run dev
```

访问 `http://127.0.0.1:4173`。端口被占用时可用 `PORT=4174 npm run dev`。

1. 点击“新建项目”，选择短剧、漫剧或通用故事；也可以先去灵感库记录想法。
2. 沿灵感、创作简报、世界观、人物、大纲推进，随后建立分集与分场。
3. 在正文编辑器写作，重要节点使用“保存快照”。
4. 按需添加知识来源和 AI 连接；审阅候选后再插入、追加或替换。
5. 在“我的项目”中备份、导出或归档；换设备前建议导出完整备份。

## 当前功能

- **项目与结构**：创建、切换、重命名、归档和恢复；分集/分场支持创建、排序、复制、删除及删除后的撤销。Markdown 导出遵循当前幕、集、场顺序，并保留正文、大纲及可恢复的孤立内容。
- **独立灵感库**：新增、编辑、搜索、归档、恢复、Markdown 导出，以及追加到当前项目的核心灵感。归档灵感只读，恢复后可继续编辑；Markdown 导出包含活动与归档灵感。
- **版本与保存**：编辑后自动保存，也可手动保存；手动快照和 AI 采纳快照记录完整内容与来源。历史版本可预览并恢复为新版本。
- **AI 协作**：支持停止、重试、光标插入、替换、追加、撤销和重做。结果先进入候选区。采纳期间禁止重复提交；保存失败时，未继续编辑的正文回到采纳前并保留候选，等待期间新增的输入则留在编辑器中并显示保存错误。
- **分镜与图片**：项目内切换创作／分镜／素材，按文字、拆镜、图片和视频选择已有资源；结构化项目计划先审阅再采纳。镜头可编辑运镜、起止状态并固定参考版本，真实图片先自动收录为候选，再由用户明确选用。Codex 图片适配为版本相关的个人实验性接入，不保证任意账号或 CLI 版本可用。
- **知识检索**：只读导入 Markdown/TXT，查看导入报告、搜索片段、选择本次引用、重新选择目录同步；可选本机 Ollama 语义索引及覆盖率提示。
- **检查更新**：底栏“检查更新”按需读取 GitHub Releases，展示当前/最新版本、平台、日期与发布说明；可打开发布页或匹配的安装包链接。启动时不自动联网，不自动安装或替换应用。
- **界面**：暖纸、墨色、琥珀配色，浅色/深色主题；编辑器主导布局、专注模式、命令面板、可见键盘焦点、减少动效支持及窄屏抽屉。项目列表、灵感、知识来源和连接中心使用统一组件。

原生关闭回调会先等待未保存灵感，再保存项目；任一步失败或仍存在新修改时保留窗口。浏览器离开页面时通过未保存提示保护草稿，但不能替代主动保存与备份。

## 备份、归档与恢复

点击左上角项目名称打开“我的项目”。

| 操作 | 包含内容 | 恢复行为 |
| --- | --- | --- |
| 备份当前项目 | 当前项目的正文、结构、版本、知识片段与引用 | 用“恢复备份”导入为独立项目，原项目保留 |
| 备份全部项目与灵感 / 完整备份 | 活动项目、归档项目、活动与归档灵感，以及兼容迁移保留的旧项目副本 | 用“恢复备份”合并为新标识的独立副本，已有项目与灵感保留 |
| 导出 Markdown | 项目正文与大纲，或灵感库可读文本 | 用于阅读、交付和外部编辑；不是可恢复项目结构的 JSON 备份 |
| 恢复上一份内部快照 | 上一次已保存的完整库状态，包括项目、归档与灵感 | 确认后将当前库回到该状态，当前已保存状态成为新的上一份快照 |

JSON 备份采用紧凑格式，不携带可重建的词向量、语义向量、连接配置或密钥；导入时重建文本检索向量，语义索引需在目标设备重新建立。单个项目备份不包含独立灵感库，跨设备迁移全部创作内容应使用完整备份。

这里的 JSON“完整备份”不包含图片／视频字节，不能代替媒体备份。`.acwpack`“完整项目包”包含单个项目的结构、媒体元数据和真实文件，恢复时创建独立项目；它不等于全部项目与灵感的库备份。隔离桌面已验收真实六镜头项目的正常往返，固定参考和选用图片正确重映射，恢复文件与原文件 SHA-256 一致。已有局部中断恢复证据不代表所有断电、磁盘不足或平台异常均通过；迁移唯一副本前仍应保留原项目、原素材和导出包。

完整备份会尝试先保存当前修改。保存失败时仍可导出已保存的库，并尝试额外导出当前项目草稿；未通过校验或保存失败的灵感草稿不保证包含在该备份中，请查看界面提示。

“归档当前项目”将项目移出活动库，可通过“查看归档项目”恢复并打开；归档能释放活动项目库空间。灵感归档是列表状态切换，灵感仍在活动库内，不释放这一配额。

内部快照只保留上一份，后续成功写入会滚动替换，不能代替长期备份。恢复前应保存或导出需要保留的未保存修改；如果中间没有新的写入，再次恢复可回到恢复前的已保存状态。库无法正常载入时，会显示恢复面板，提供导出原始数据、恢复上一份内部快照和重新打开。原始恢复数据供排障使用，不属于普通“恢复备份”接受的项目/完整库格式。

桌面导出保存到系统下载目录，使用唯一文件名避免覆盖已有文件；浏览器导出由浏览器下载设置接管。

## AI 请求与引用

“发送范围”展示本次将发送的上下文条目、字符数及截断状态。请求在异步确认、凭据读取和网络调用前冻结，生成过程中的界面切换不会改变已准备的请求。

- 请求总预算为 **24,000 字符**，包含系统说明与用户消息；这里是字符预算，不是模型 token 数。
- 创作要求最多 12,000 字符，超出时明确拒绝；预算内的要求完整保留。
- 当前正文/大纲最多 9,000 字符；引用检查同时带上真正正文及最多 1,500 字符的引用笔记。
- 按勾选状态加入上游资料与人物，每篇最多 2,800 字符；最多考虑 6 条知识片段，每条最多 900 字符。
- 总预算不足时进一步截断上下文并标记；候选与版本只保存实际发出的知识内容，不把未发送的整段资料当作引用。

正文、上游资料及知识内容会发送给当前执行端；选择本机 CLI 也可能使用云端模型。连接中心的“设为当前 AI”只切换后续请求，不立即调用模型。

## 知识库与语义检索

通过文件选择器授权 `.md`、`.markdown`、`.txt` 文件或目录；Obsidian 接入是选择 Vault 目录并只读导入文本，不控制 Obsidian 应用，也不写回 Vault。

单次最多接受 **80 个文件**，单文件不超过 **1 MiB**，累计不超过 **4 MiB**。遇到不支持、过大或超出容量的文件会跳过并继续考虑后续文件；预览与导入报告列出跳过原因，空文件不会建立索引。每项目最多保留 **2,000 个片段**，超过时会提示保留数量。

默认按自然文本边界切片，用 384 维稳定哈希词向量做本地文本检索。它可重建，不等同于神经网络 Embedding。

填写本机已安装的 Ollama Embedding 模型，点击“建立 / 更新语义索引”，应用通过 `http://127.0.0.1:11434/api/embed` 生成语义向量；桌面模式经 Rust 调用。未变化片段复用缓存，资料删除或修改后清理失效缓存，界面显示“已索引 / 总片段”和待更新数。更换模型需重新建立索引；调用失败时提示并回退到文本检索，不自动下载模型。接口参考：[Ollama Embeddings](https://docs.ollama.com/api/embed)。

“重新选择目录并同步”更新新增、修改和删除的文件，需要用户重新选择原目录；移除旧文件前有确认。未变化的所选引用尽量保留，失效引用和语义缓存会清理。当前不后台监听目录，不解析 Obsidian 标签、双链或插件数据库。

## AI 执行端

| 类型 | 当前实现与前提 |
| --- | --- |
| OpenAI 兼容 API | `/models` 检测及 `/chat/completions` 生成；支持 SSE 与普通 JSON 返回。浏览器直连受 CORS 限制，桌面由 Rust 请求 |
| Ollama | `/api/tags` 发现模型及 `/api/chat` 生成；需自行启动服务并安装模型 |
| Codex CLI | 先运行 `codex login`；只读、非持久化模式，读取最后答复。使用默认供应商，忽略用户自定义供应商配置与规则 |
| Claude Code | API Key 或既有 CLI 登录态；无 Key 时尝试 `claude auth login` 建立的登录态。Key 分支采用 `--bare`、禁用工具与会话持久化、临时隔离 HOME；登录分支关闭普通设置源、工具、MCP、技能和普通 hooks，组织托管策略仍可能生效 |
| Antigravity CLI | 检测 `agy`，先在终端登录；使用当前默认模型、Plan 与 sandbox 固定参数。用户配置、插件、hooks 和权限规则仍可能生效，不属于无工具执行 |
| Gemini CLI | 仅检测安装，不开放创作执行 |

CLI 在确认账号及上下文使用后执行，可选择本次会话不再询问同一执行端。安装检测不等于登录、额度或真实生成已经验证。Intel CLI 在 Apple Silicon 上会标明兼容模式与实验状态。

Codex 默认沿用现有 CLI 登录态及本机模型设置，不需要另填模型 ID。工作台通过 CLI 的只读 `config/read` 取得有效模型，仅将模型 ID 传入隔离生成，不继承 hooks、MCP、执行规则或自定义供应商；读取失败时停止，不改用模型目录中的推荐默认项。可在“连接中心 → Codex CLI → 模型设置”填写可选规划模型覆盖值，用于文字生成及图片规划。保存不会调用生成或验证账号权限，失败不会自动换模型或转 API。CLI 版本号与规划模型分开保存，底层图片模型以实际回执为准；更换规划模型后，文字 CLI 执行许可需按原有规则重新确认。

Codex 失败提示只保留安全诊断：文字执行的退出码、CLI 报告的线程／轮次阶段及请求规划模型，图片协议的失败阶段、已知错误类别和有效上游 HTTP 状态（若有）。文字使用 `--json`，只从已知错误事件分类，不把正文或工具输出当作诊断；命令行选项、字段类型、未知／缺少字段、未知方法和请求参数分别提示。CLI 阶段不是远端已执行或计费的证明。参数错误不会仅因含 `model` 就被当成模型权限问题；未分类错误明确保留未知，不展示或持久化原始事件、日志、提示词、路径或凭据。请求规划模型不是底层图片模型或账号可用性证明。旧失败记录保持原样，新的诊断不能追溯补出已丢失的上游信息。

若文字轮次明确报告 ChatGPT 登录方式不支持所选模型，应用会展示该原因及 CLI 错误信封中的合法 HTTP 状态（若有），不让模型缓存等 stderr 警告覆盖轮次错误。应先在现有 CLI 中确认账号可用模型；工作台不会自动换模型、改登录方式或切换计费路径。具体调用结果不代表该模型在所有产品或账号中不可用。

CLI 由固定白名单驱动和参数运行，使用临时工作目录，不接受任意 Shell、参数、路径或环境变量；设有请求、输出、并发和超时限制。Codex、Claude 登录分支和 Antigravity 使用用户登录目录，不能理解为完整进程隔离或操作系统级沙箱。Antigravity 协议参考：[Headless](https://antigravity.google/docs/cli/headless/)、[权限规则](https://antigravity.google/docs/cli/permissions/)。

API Key 默认只在页面会话内存中；macOS 桌面可明确选择系统钥匙串保存，按连接和地址隔离。Key 不进入项目数据库或 JSON 备份。模型与 CLI 调用可能消耗服务账号额度。

### 媒体 API／CLI 通用接入框架

连接中心的“媒体协议框架”从桌面后端读取已实现的适配器、输入模式、参考用途及查询／取消边界。新增图片或视频 API 连接时必须明确选择协议；旧连接只对缺失的历史协议做兼容，未知协议不会被重写成 Veo 或 Images，也不会自动换供应商。

目前迁入框架的是 OpenAI Images API、Gemini Veo API 和 Codex 原生图片 CLI。统一处理固定输入、整批预检、排队、取消本地等待、持久化及素材收录；各适配器负责协议校验、提交和不重新生成的恢复。已实现不等于账号、模型、额度或真实生成已验证。当前没有可用的视频 CLI 驱动，远端取消也未实现；不能把停止本地等待理解为停止计费。

扩展供应商需实现并注册受审查的适配器，不是填任意 URL 或 Shell 就能兼容。API 的认证、异步句柄、轮询和下载协议需逐项实现；CLI 仍使用固定白名单、隔离目录和真实产物校验。按用户当前选择，先完成框架，不先新增 Runway／fal 等供应商或安装 CLI，不发起收费视频生成。扩展契约见 [多模态实现契约](specs/多模态实现契约.md)。

媒体／项目包选择器已接入官方 Tauri dialog 插件，通过后端打开父窗口原生文件面板；不向前端开放通用文件系统权限。媒体预览仅对应用受控媒体协议放行，未开放任意本机路径。隔离 QA 已验证真实 Codex 图片生成、参考输入、自动收录及完整包恢复；正式发布、其他供应商和真实视频仍需单独验收。

## 本地媒体工具（多模态升级）

媒体导入和生成结果收录使用 FFprobe 探测尺寸／时长，再用 FFmpeg 实际解码一帧；视频关键帧提取也使用 FFmpeg。因此图片功能同样需要这两项工具，不仅视频或未来的粗剪需要。纯文字创作不依赖它们。

当前实现调用本机外部工具，安装包未配置随包携带、自动下载或安装。运行时依次在 `/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin` 查找 `ffprobe` 和 `ffmpeg`，不读取任意自定义路径或通过 Shell 执行命令。缺少任一工具时明确报错；生成入口在登记任务和调用供应商前检查工具是否存在。存在不代表可执行、所需格式可解码或性能符合要求，执行阶段仍会报告启动、解码或超时错误。

Apple Silicon 发行验收须同时核对应用与外部工具的架构，不能由应用为 arm64 推断工具也是 arm64。Intel 工具的本机兼容运行不能替代原生架构或其他设备验收；当前路径发现也不代表 Windows 媒体工具已经适配。不要自动安装 Rosetta 或第三方二进制来绕过错误。

FFmpeg 的具体许可证取决于实际构建选项，不能把任意二进制一概当成 LGPL。当前没有将本机工具复制进应用或发布附件；如以后随包分发，须先确定对应版本、架构、构建选项、第三方组件、许可证声明及匹配源码的提供方式，再修改打包配置。[FFmpeg 官方许可证说明](https://ffmpeg.org/legal.html)。

这些工具用于本地校验与抽帧，不是图片／视频 AI 供应商；它们可用不等于模型登录、额度、参考图输入或真实生成已验证。

## 数据存储

桌面数据库位于 Tauri 应用数据目录中的 `workbench.sqlite3`，使用 SQLite 事务、WAL 与 FULL 同步；浏览器使用 IndexedDB 原子事务。保存校验版本号，拒绝旧窗口覆盖已更新数据。

逻辑活动库上限为 **64 MiB**，归档项目上限为 **448 MiB**，外部备份/导入上限为 **512 MiB**；实际浏览器可用空间仍受其配额限制。上一内部快照也占用存储，文件的物理体积不等于逻辑活动库大小。

旧版 localStorage 只在新库不存在时迁移，旧数据保留为回退副本。只有完整匹配旧版未编辑模板的项目会被隐藏，并保留恢复副本；已编辑项目保留。浏览器和桌面是独立存储，可通过 JSON 备份迁移，不自动同步。

```bash
npm run desktop:build:mac
```

当前构建配置输出到：

- `src-tauri/target/aarch64-apple-darwin/release/bundle/macos/AI Creator Workbench.app`

这些是本机构建的预期路径；公开安装包以 [GitHub Releases](https://github.com/Errorrrrr/ai-creator-workbench/releases) 中已发布的附件为准。当前只交付 macOS 12.3+ 的 Apple Silicon 版本，为 ad-hoc 签名，尚无 Apple Developer ID 签名或公证。

## 更新与 GitHub Actions 发布

点击底栏“检查更新”，可查看版本、发布说明及适合当前平台的下载入口，也可以手动“重新检查”或“打开发布页”。检查只在主动点击时联网。网络失败、没有已发布版本或 GitHub API 限流时会显示结果，不影响本地创作。

更新使用当前仓库 `Errorrrrr/ai-creator-workbench` 的 Releases。匿名检查要求仓库和目标 Release 公开；草稿或私有仓库不会被当作公开更新。界面的“下载匹配安装包”打开浏览器下载地址，安装仍由用户完成。升级前建议导出完整备份，关闭旧应用后再替换应用；项目数据库保存在独立的应用数据目录中。

推送已有版本 tag（如 `v0.3.0`）触发 [Release macOS 工作流](.github/workflows/release.yml)。流程先核对 tag 与所有版本文件，执行 JavaScript 检查、测试、前端构建和锁定依赖的 Rust 测试，再构建 Apple Silicon `.app` 与 `.dmg`。安装包、签名结构、架构和 SHA-256 校验通过后，才发布完整 GitHub Release。

发布附件名称固定为：

- `ai-creator-workbench_0.3.0_aarch64.dmg`
- `ai-creator-workbench_0.3.0_aarch64.app.zip`
- `SHA256SUMS`

构建 job 只有仓库读取权限，发布 job 使用 GitHub 自带 `GITHUB_TOKEN` 的 `contents: write`，不需要在源码中放置发布 token 或自动更新签名密钥。失败的上传只会留下未公开的草稿；已经公开的版本不会被工作流覆盖。预发布与旧版本不会抢占 Latest。

具体版本步骤、手动重试、校验和当前签名边界见 [GitHub Actions 发布说明](specs/GitHub-Actions发布.md)。

## 快捷键与当前边界

- `⌘/Ctrl + K`：命令面板。
- `⌘/Ctrl + S`：保存当前文档；在灵感库保存当前灵感。
- `⌘/Ctrl + Enter`：执行 AI 请求。
- `Esc`：关闭弹层、抽屉或停止生成。

浏览器布局覆盖窄屏使用；原生窗口当前最小为 1024 × 700。多模态升级尚未完成真实图片／视频闭环验收；已有控件和适配源码不应当作正式可用能力。尚未提供应用内成片渲染、多人协作、云同步、后台文件监听、Obsidian 双向写回、Gemini 创作执行、自动下载安装更新或正式 Windows 发布。真实桌面交互、真实供应商/CLI/Embedding 调用与正式发布仍需在对应环境验收。

更完整的交互规则见 [交互说明](specs/交互说明.md)，视觉规范见 [设计系统](design-system/ai-creator-workbench/MASTER.md)。

# AI 创作工作台

面向灵感、故事设定、短剧与漫剧剧本的本地优先写作工具。支持多项目、独立灵感库、知识检索和可切换的 AI 执行端。没有配置 AI 时，仍可创建、编辑、备份和恢复内容。

工程名：`ai-creator-workbench`，当前源码版本：`0.12.0`。浏览器模式使用 IndexedDB，Tauri 2 桌面模式使用 SQLite。首次启动为空白工作台，新项目不预填示例正文、分集或分场。

本版支持新生成图片自动关联并选用到原镜头、多场批量生图及单场素材包导出。详见 [v0.12.0 发布说明](specs/发布说明-v0.12.0.md)。

v0.4.0 的 P0 文字闭环和 P1 分镜／图片主路径已在 macOS 隔离桌面环境完成验收：现有 Codex CLI 生成六镜头及带固定参考的真实图片，候选明确选用、重启保存和完整项目包恢复通过。视频阶段目前按用户选择先提供通用接入框架，真实视频生成尚未验收。公开发布结果以 [GitHub Releases](https://github.com/Errorrrrr/ai-creator-workbench/releases) 为准。范围和逐项证据见 [多模态实施契约](specs/多模态实现契约.md)，更新要点见 [v0.4.0 发布说明](specs/发布说明-v0.4.0.md)。

## 开始使用

浏览器开发模式要求 Node.js 18 或更高版本：

```bash
npm run dev
```

访问 `http://127.0.0.1:4173`。端口被占用时可用 `PORT=4174 npm run dev`。

1. 点击“新建项目”，选择短剧、漫剧或通用故事；也可以先去灵感库记录想法。
2. 沿灵感、创作简报、世界观、人物、大纲推进，随后建立分集与分场。
3. 在正文编辑器写作，重要节点使用“保存快照”。
4. 按需添加知识来源和 AI 连接；审阅候选后再插入、追加或替换。
5. 在“我的项目”中备份、导出或归档；换设备前建议导出完整备份。

## 当前功能

- **界面与操作层级**：默认收起 AI 助手，右上角“AI 助手”可随时打开；窄窗口使用抽屉，避免挤压正文和分镜。前期资料可折叠，进入对应文档或搜索命中时自动展开。步骤条保留当前步骤，前后切换和说明按需展开。分镜区将导出与低频操作归组，镜头列表与详情分开浏览；参考、衔接和生成设置按用途展开。折叠只影响显示，不停止任务或丢弃编辑。
- **角色形象**：在“人物小传”点击“生成角色正脸与三视图”，或在素材库选择“从人物小传生成角色图”。支持按 Markdown 表格或标题选择单个角色，核对小传、补充外观和视觉风格，再使用项目图片执行端生成一张左侧正脸特写、右侧正面／90 度侧面／背面全身三视图的参考图。完成后自动保存到角色素材；同名角色重新生成保留独立版本，可使用已有角色图固定形象。任务支持取消等待和中断后收录，生成失败不会创建空素材。此流程复用图片适配器，仍需配置图片执行端和账号；文字 CLI 不自动获得图片能力。
- **项目与结构**：创建、切换、重命名、归档和恢复；分集/分场支持创建、排序、复制、删除及删除后的撤销。Markdown 导出遵循当前幕、集、场顺序，并保留正文、大纲及可恢复的孤立内容。
- **独立灵感库**：新增、编辑、搜索、归档、恢复、Markdown 导出，以及追加到当前项目的核心灵感。归档灵感只读，恢复后可继续编辑；Markdown 导出包含活动与归档灵感。
- **版本与保存**：编辑后自动保存，也可手动保存；手动快照和 AI 采纳快照记录完整内容与来源。历史版本可预览并恢复为新版本。
- **AI 协作**：支持停止、重试、光标插入、替换、追加、撤销和重做。结果先进入候选区。采纳期间禁止重复提交；保存失败时，未继续编辑的正文回到采纳前并保留候选，等待期间新增的输入则留在编辑器中并显示保存错误。
- **待审稿**：候选按项目、文档和页签保存，切换后可恢复；重新生成另存一稿，停止或中断的内容标为部分稿。每项目最多 100 份，到限后提示先采纳或移除，不自动淘汰旧稿。请求快照与生成时原文一起保存并随项目 JSON／完整项目包备份；分镜 JSON 的手动校正也保存。
- **差异审阅**：文字候选的“审阅替换差异”和项目计划预览提供逐行增删高亮、变更统计、前后跳转及全文查看。候选与生成时原文对比；正文后来有修改时显示提示并继续阻止覆盖。项目计划仍整批校验、原子采纳，手工计划不会移除其他 AI 待审稿。
- **分镜与图片**：项目内切换创作／分镜／素材，按文字、拆镜、图片和视频选择已有资源；结构化项目计划先审阅再采纳。镜头可编辑运镜、起止状态并固定参考版本，镜头新生成图片完成后自动关联并选用，旧图仍保留为候选；已生成但未关联的结果会补齐，生成期间的手动选用不会被该任务覆盖。视频保留手动选用与审核。Codex 图片适配为版本相关的个人实验性接入，不保证任意账号或 CLI 版本可用。
- **分集／分场浏览分镜**：按项目结构选择分集和分场；左侧选择分场时，分镜区保持打开并显示该场镜头。“查看全集”按分场顺序汇总当前集。导出 Flow／Muse 和普通批量生成计划使用当前查看范围；完整项目包仍包含全项目。新建镜头归入所选来源，替换候选与排序只影响同一来源，旧的无来源镜头可从“其他内容与未归属”查看。
- **单场导出与多场生图**：点击「导出 → 导出单个分场…」，独立选择一个剧本分场，导出该场全部镜头的 Muse／Flow 提示词与固定参考图，保存到设置的导出文件夹。点击「多场批量生图」可跨分集勾选多个分场，再按镜头选择；按项目中的分集／分场顺序预览后确认提交，每批最多 20 镜、最多 3 个任务同时执行，其余排队。新图片完成后自动关联并选用到原镜头，旧版本保留，失败不会自动重试。分场没有分镜时需先拆镜。
- **分镜候选**：采纳或替换成功后，在同一次保存中移除对应待审稿并清空当前候选；失败时保留供重试。旧分镜候选不随启动、切换分场或刷新自动展示，需从“查看历史候选”手动打开。候选卡片标明生成时间（精确到秒）和批次；没有时间记录的旧稿明确标为未记录。
- **拆镜任务进度**：每次拆镜关联原分场与任务编号，在分镜区和任务中心显示准备、确认、等待返回、接收、绑定保存和最终结果，以及耗时与已收字符数。任务结束前禁止再开拆镜；停止后等待执行端退出再解锁。执行时可浏览其他分场，结果仍保存到原分场。任务进度记录限本次会话，候选与已保存分镜随项目持久保存。冲突检查只比较原分场剧本和镜头，其他分场变化不阻止采纳；旧候选追加兼容，替换前明确确认。
- **拆镜自动配置**：首次 AI 拆镜成功后自动追加并保存镜头；已有镜头时先选择替换重做、追加或仅生成候选，替换前保留历史版本供恢复，填好画面、动作、运镜、时长和衔接信息，并记录角色、场景和道具名称，自动关联素材当前选用的图片。旧镜头会用画面、动作和来源分场标题匹配素材库中的名称（不扫描对白或整场剧本），无需重新拆镜；导入图片、生成图片或选用版本后也会自动补齐缺失引用。仅补充，不替换已有固定版本；手动移除的素材会记为排除，后续补图不会擅自加回。详情可分别填写三类名称（留空表示没有）、手动多选、恢复按内容识别或恢复已排除素材。地点时段冲突、重名或缺图时显示待处理；旧镜头使用本地名称匹配，别名或未明确写出的实体仍需补充名称。停止、中断、解析失败、保存失败或生成期间内容变化时保留候选；旧候选不会自动展示或采纳。Flow／Muse 导出会携带对应参考图片并提示缺失项。
- **媒体交互**：自动关联的角色、场景、道具图作为一致性参考保留；图生视频默认上传已选用分镜图作为首帧，详情展示本次上传项。参考生视频仍附加主体参考，手动标记为视频输入的项严格按模式校验。素材名称／用途草稿按项目和素材保留在本次会话，轮询和切换页面不会覆盖；保存失败保留输入，关闭或更新前需保存或放弃修改。任务中心显示创建／更新时间、按实际生成版本判断选用与审核状态，可定位来源镜头或本次生成版本。专注模式入口在顶部，创作／分镜／素材页共用，⌘P 会退出专注并聚焦内容搜索；镜头列表刷新保留键盘焦点，菜单内 Esc 只关闭菜单。
- **全局网络代理**：桌面版在“连接中心 → 全局网络代理 → 代理设置”统一选择自动、手动或直连。覆盖所有文字 CLI（Antigravity、Codex、Claude）、Codex 图片 CLI、文字／图片／视频 API 的提交、查询和媒体下载，以及连接测试、Embedding 和应用更新请求。设置独立于项目保存在本机应用配置中，所有项目共用，下一次新建连接或启动 CLI 时生效，不改变正在执行的连接。自动模式优先沿用环境变量，否则读取当前 macOS HTTP／HTTPS 系统代理及排除项；手动模式使用不含账号密码的 HTTP／HTTPS 代理地址，直连模式清除继承的代理。localhost、127.0.0.1、::1 保持直连以支持本机服务。PAC／自动发现或仅 SOCKS 系统配置暂不自动转换。浏览器开发版仍由浏览器与服务进程管理代理，桌面全局设置不适用于浏览器。
- **Google Flow 导出**：桌面版分镜工具栏点击「导出 → Google Flow 素材包」，在导出目录生成独立文件夹。按镜头顺序保存 `prompt.txt`、中文说明及固定版本的参考图片，附总说明与 `manifest.json`。在 Flow 中逐镜头复制提示词、上传参考图或首尾帧即可，无需配置视频执行端。本功能不是 Flow 一键导入接口，不包含续接视频；未绑定图片、来源变更会写入说明，绑定版本缺失、文件缺失或长度异常时导出失败并清理半成品。
- **Muse 聊天导出**：分镜工具栏点击「导出 → Muse 聊天素材包」，生成包含项目名、当前分集／分场、包类型和本机时间的文件夹，例如 `狂澜之上_EP01-SC001_Muse 聊天素材包_20261024-160000`。每镜头包含可发送给 [muse.ai](https://muse.ai/) 的 `prompt.txt`、对应参考图片、中文说明及 `修改消息.txt` 模板。消息明确请求 Meta Muse Video 生成视频，并写入画面、动作、运镜、对白、目标时长／画幅和附件用途；建议每镜头新建聊天，修改结果时在原聊天继续。无需配置 API，也不会自动上传或提交生成。首尾画面和多图一致性属于创作要求，支持情况以实际账号反馈为准；不把未核实能力写成模型参数。产品与模型依据：[Meta Muse](https://ai.meta.com/muse/)、[Muse Video](https://ai.meta.com/blog/introducing-muse-image-muse-video-msl/)。
- **知识检索**：只读导入 Markdown/TXT，查看导入报告、搜索片段、选择本次引用、重新选择目录同步；可选本机 Ollama 语义索引及覆盖率提示。
- **检查更新**：底栏“检查更新”按需下载 GitHub Releases 中的静态 `latest.json` 更新清单，展示当前/最新版本、平台、日期与发布说明；桌面版可选择“更新并重启”，在应用内完成签名下载、保存、安装和重启；仍保留安装包链接。启动时不自动联网。
- **界面**：暖纸、墨色、琥珀配色，浅色/深色主题；编辑器主导布局、专注模式、命令面板、可见键盘焦点、减少动效支持及窄屏抽屉。项目列表、灵感、知识来源和连接中心使用统一组件。

v0.5.0 的候选稿保留、修改差异审阅和写作区空间优化已完成浏览器回归及 macOS 隔离原生应用验收：使用本机固定响应验证文字稿保留、差异跳转、生成中正常退出后的 SQLite 恢复，以及文字与项目计划采纳；本轮没有调用真实供应商。更新内容见 [v0.5.0 发布说明](specs/发布说明-v0.5.0.md)，逐项证据见 [2026-10-15 优化验收](specs/优化验收-2026-10-15.md)，公开安装包以 [GitHub Releases](https://github.com/Errorrrrr/ai-creator-workbench/releases) 的实际附件为准。创作目标、步骤说明和助手上下文可按需展开，重复纸面标题隐藏，保留原有配色与写作字体。

原生关闭回调会先等待未保存灵感，再保存项目；任一步失败或仍存在新修改时保留窗口。浏览器离开页面时通过未保存提示保护草稿，但不能替代主动保存与备份。

## 备份、归档与恢复

点击左上角项目名称打开“我的项目”。

| 操作 | 包含内容 | 恢复行为 |
| --- | --- | --- |
| 备份当前项目 | 当前项目的正文、结构、版本、待审稿及其请求快照、知识片段与引用 | 用“恢复备份”导入为独立项目，原项目保留 |
| 备份全部项目与灵感 / 完整备份 | 活动项目、归档项目、活动与归档灵感，以及兼容迁移保留的旧项目副本 | 用“恢复备份”合并为新标识的独立副本，已有项目与灵感保留 |
| 导出 Markdown | 项目正文与大纲，或灵感库可读文本 | 用于阅读、交付和外部编辑；不是可恢复项目结构的 JSON 备份 |
| 恢复上一份内部快照 | 上一次已保存的完整库状态，包括项目、归档与灵感 | 确认后将当前库回到该状态，当前已保存状态成为新的上一份快照 |

JSON 备份采用紧凑格式，不携带可重建的词向量、语义向量、连接配置或密钥；导入时重建文本检索向量，语义索引需在目标设备重新建立。单个项目备份不包含独立灵感库，跨设备迁移全部创作内容应使用完整备份。

这里的 JSON“完整备份”不包含图片／视频字节，不能代替媒体备份。`.acwpack`“完整项目包”包含单个项目的结构、媒体元数据和真实文件，恢复时创建独立项目；它不等于全部项目与灵感的库备份。隔离桌面已验收真实六镜头项目的正常往返，固定参考和选用图片正确重映射，恢复文件与原文件 SHA-256 一致。已有局部中断恢复证据不代表所有断电、磁盘不足或平台异常均通过；迁移唯一副本前仍应保留原项目、原素材和导出包。

完整备份会尝试先保存当前修改。保存失败时仍可导出已保存的库，并尝试额外导出当前项目草稿；未通过校验或保存失败的灵感草稿不保证包含在该备份中，请查看界面提示。

“归档当前项目”将项目移出活动库，可通过“查看归档项目”恢复并打开；归档能释放活动项目库空间。灵感归档是列表状态切换，灵感仍在活动库内，不释放这一配额。

从 v0.4.2 起，活动项目和归档项目右侧均提供“删除”。确认后永久移除项目正文、结构、历史版本、知识资料及项目内的图片、视频和任务记录，内部快照不能恢复该项目；此前导出的备份和外部原始文件保留。媒体任务仍在运行时须先停止并等待结束。媒体文件清理中断会保留待办记录，在下次启动时重试。删除当前项目会切换到其他活动项目，删除最后一个项目后回到空项目状态。

内部快照只保留上一份，后续成功写入会滚动替换，不能代替长期备份。恢复前应保存或导出需要保留的未保存修改；如果中间没有新的写入，再次恢复可回到恢复前的已保存状态。库无法正常载入时，会显示恢复面板，提供导出原始数据、恢复上一份内部快照和重新打开。原始恢复数据供排障使用，不属于普通“恢复备份”接受的项目/完整库格式。

桌面版可从「数据与备份 → 设置导出文件夹」选择统一导出位置，全部项目共用，仅保存在本机。未设置或点击「恢复默认位置」时，保存到系统下载目录。设置适用于 Flow／Muse 素材包、选用视频包、完整项目包、单个素材、Markdown 与 JSON 备份；不会移动已有文件，也不会随项目备份迁移。自定义目录失效或无写入权限时会报错，可重新选择或恢复默认位置。

导出名称使用项目／素材名、范围（分镜包）、类型与本机时间，长名称按文件系统限制截短并移除路径字符；同秒重复导出自动追加 ` (2)`、` (3)` 等序号，不覆盖已有文件或文件夹。镜头内部仍保留 `shot-001` 等编号与原始镜头标识，供外部视频回填匹配。浏览器导出由浏览器下载设置接管。

## AI 请求与引用

“发送范围”展示本次将发送的上下文条目、字符数及截断状态。请求在异步确认、凭据读取和网络调用前冻结，生成过程中的界面切换不会改变已准备的请求。

- 请求总预算为 **24,000 字符**，包含系统说明与用户消息；这里是字符预算，不是模型 token 数。
- 创作要求最多 12,000 字符，超出时明确拒绝；预算内的要求完整保留。
- 当前正文/大纲最多 9,000 字符；续写优先使用末尾内容，并在发送范围中标明截断方向。参考笔记可勾选纳入上下文，最多 1,500 字符；引用检查默认包含。
- 按勾选状态加入上游资料与人物，每篇最多 2,800 字符；最多考虑 6 条知识片段，每条最多 900 字符。
- 总预算不足时进一步截断上下文并标记；候选与版本只保存实际发出的知识内容，不把未发送的整段资料当作引用。

正文、上游资料及知识内容会发送给当前执行端；选择本机 CLI 也可能使用云端模型。连接中心的“设为当前 AI”只切换后续请求，不立即调用模型。

## 知识库与语义检索

通过文件选择器授权 `.md`、`.markdown`、`.txt` 文件或目录；Obsidian 接入是选择 Vault 目录并只读导入文本，不控制 Obsidian 应用，也不写回 Vault。

单次最多接受 **80 个文件**，单文件不超过 **1 MiB**，累计不超过 **4 MiB**。遇到不支持、过大或超出容量的文件会跳过并继续考虑后续文件；预览与导入报告列出跳过原因，空文件不会建立索引。每项目最多保留 **2,000 个片段**，超过时会提示保留数量。

默认按自然文本边界切片，用 384 维稳定哈希词向量做本地文本检索。它可重建，不等同于神经网络 Embedding。

填写本机已安装的 Ollama Embedding 模型，点击“建立 / 更新语义索引”，应用通过 `http://127.0.0.1:11434/api/embed` 生成语义向量；桌面模式经 Rust 调用。未变化片段复用缓存，资料删除或修改后清理失效缓存，界面显示“已索引 / 总片段”和待更新数。更换模型需重新建立索引；调用失败时提示并回退到文本检索，不自动下载模型。接口参考：[Ollama Embeddings](https://docs.ollama.com/api/embed)。

“重新选择目录并同步”更新新增、修改和删除的文件，需要用户重新选择原目录；移除旧文件前有确认。未变化的所选引用尽量保留，失效引用和语义缓存会清理。当前不后台监听目录，不解析 Obsidian 标签、双链或插件数据库。

## AI 执行端

| 类型 | 当前实现与前提 |
| --- | --- |
| OpenAI 兼容 API | `/models` 检测及 `/chat/completions` 生成；支持 SSE 与普通 JSON 返回。浏览器直连受 CORS 限制，桌面由 Rust 请求 |
| Ollama | `/api/tags` 发现模型及 `/api/chat` 生成；需自行启动服务并安装模型 |
| Codex CLI | 先运行 `codex login`；只读、非持久化模式，读取最后答复。使用默认供应商，忽略用户自定义供应商配置与规则 |
| Claude Code | API Key 或既有 CLI 登录态；无 Key 时尝试 `claude auth login` 建立的登录态。Key 分支采用 `--bare`、禁用工具与会话持久化、临时隔离 HOME；登录分支关闭普通设置源、工具、MCP、技能和普通 hooks，组织托管策略仍可能生效 |
| Antigravity CLI | 检测 `agy`，先在终端登录；使用当前默认模型、Plan 与 sandbox 固定参数。用户配置、插件、hooks 和权限规则仍可能生效，不属于无工具执行 |
| Gemini CLI | 仅检测安装，不开放创作执行 |

各 CLI 卡片统一通过“设置”查看登录、配置来源和支持状态。Codex 设置保留可选规划模型；Claude 设置内的“API Key（可选）”按需展开，留空保存保持现有 Key 与保存方式不变。打开设置不会读取或回填密钥，不会调用生成。所有 CLI 继续共用连接中心的全局网络代理。安装检测与上次实际调用结果分开显示；重新检测不会清除调用失败，修改模型或 Key 后恢复待验证。Claude 钥匙串读取失败仅影响 Claude，不自动换用其他凭据；设置中可显式移除工作台会话及钥匙串 Key，启动环境的 Key 仍可能优先于 CLI 登录。

CLI 在确认账号及上下文使用后执行，可选择本次会话不再询问同一执行端。安装检测不等于登录、额度或真实生成已经验证。Intel CLI 在 Apple Silicon 上会标明兼容模式与实验状态。

Codex 默认沿用现有 CLI 登录态及本机模型设置，不需要另填模型 ID。工作台通过 CLI 的只读 `config/read` 取得有效模型，仅将模型 ID 传入隔离生成，不继承 hooks、MCP、执行规则或自定义供应商；读取失败时停止，不改用模型目录中的推荐默认项。可在“连接中心 → Codex CLI → 设置”填写可选规划模型覆盖值，用于文字生成及图片规划。保存不会调用生成或验证账号权限，失败不会自动换模型或转 API。CLI 版本号与规划模型分开保存，底层图片模型以实际回执为准；更换规划模型后，文字 CLI 执行许可需按原有规则重新确认。

Codex 失败提示只保留安全诊断：文字执行的退出码、CLI 报告的线程／轮次阶段及请求规划模型，图片协议的失败阶段、已知错误类别和有效上游 HTTP 状态（若有）。文字使用 `--json`，只从已知错误事件分类，不把正文或工具输出当作诊断；命令行选项、字段类型、未知／缺少字段、未知方法和请求参数分别提示。CLI 阶段不是远端已执行或计费的证明。参数错误不会仅因含 `model` 就被当成模型权限问题；未分类错误明确保留未知，不展示或持久化原始事件、日志、提示词、路径或凭据。请求规划模型不是底层图片模型或账号可用性证明。旧失败记录保持原样，新的诊断不能追溯补出已丢失的上游信息。

若文字轮次明确报告 ChatGPT 登录方式不支持所选模型，应用会展示该原因及 CLI 错误信封中的合法 HTTP 状态（若有），不让模型缓存等 stderr 警告覆盖轮次错误。应先在现有 CLI 中确认账号可用模型；工作台不会自动换模型、改登录方式或切换计费路径。具体调用结果不代表该模型在所有产品或账号中不可用。

CLI 由固定白名单驱动和参数运行，使用临时工作目录，不接受任意 Shell、参数、路径或环境变量；设有请求、输出、并发和超时限制。Codex、Claude 登录分支和 Antigravity 使用用户登录目录，不能理解为完整进程隔离或操作系统级沙箱。Antigravity 协议参考：[Headless](https://antigravity.google/docs/cli/headless/)、[权限规则](https://antigravity.google/docs/cli/permissions/)。

API Key 默认只在页面会话内存中；macOS 桌面可明确选择系统钥匙串保存，按连接和地址隔离。Key 不进入项目数据库或 JSON 备份。模型与 CLI 调用可能消耗服务账号额度。

### 媒体 API／CLI 通用接入框架

连接中心的“媒体协议框架”从桌面后端读取已实现的适配器、输入模式、参考用途及查询／取消边界。新增图片或视频 API 连接时必须明确选择协议；旧连接只对缺失的历史协议做兼容，未知协议不会被重写成 Veo 或 Images，也不会自动换供应商。

目前迁入框架的是 OpenAI Images API、Gemini Veo API 和 Codex 原生图片 CLI。统一处理固定输入、整批预检、排队、取消本地等待、持久化及素材收录；各适配器负责协议校验、提交和不重新生成的恢复。已实现不等于账号、模型、额度或真实生成已验证。当前没有可用的视频 CLI 驱动，远端取消也未实现；不能把停止本地等待理解为停止计费。

扩展供应商需实现并注册受审查的适配器，不是填任意 URL 或 Shell 就能兼容。API 的认证、异步句柄、轮询和下载协议需逐项实现；CLI 仍使用固定白名单、隔离目录和真实产物校验。按用户当前选择，先完成框架，不先新增 Runway／fal 等供应商或安装 CLI，不发起收费视频生成。扩展契约见 [多模态实现契约](specs/多模态实现契约.md)。

媒体／项目包选择器已接入官方 Tauri dialog 插件，通过后端打开父窗口原生文件面板；不向前端开放通用文件系统权限。媒体预览仅对应用受控媒体协议放行，未开放任意本机路径。隔离 QA 已验证真实 Codex 图片生成、参考输入、自动收录及完整包恢复；其他供应商和真实视频仍需单独验收，公开发布以 [GitHub Releases](https://github.com/Errorrrrr/ai-creator-workbench/releases) 的实际附件为准。

## 本地媒体工具（多模态升级）

静态图片导入和生成结果收录使用内置图片解码器，支持 PNG、JPEG、WebP、GIF，读取实际像素并检查尺寸、完整性与解码内存限制，无需安装外部媒体工具。视频仍使用 FFprobe 探测尺寸／时长，再用 FFmpeg 实际解码一帧；视频关键帧提取也使用 FFmpeg。纯文字创作不依赖媒体工具。

视频处理调用本机外部工具，安装包未配置随包携带、自动下载或安装。运行时依次在 `/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin` 查找 `ffprobe` 和 `ffmpeg`，不读取任意自定义路径或通过 Shell 执行命令。缺少任一工具时明确报错；视频生成入口在登记任务和调用供应商前检查工具是否存在。存在不代表可执行、所需格式可解码或性能符合要求，执行阶段仍会报告启动、解码或超时错误。

Apple Silicon 发行验收须同时核对应用与外部工具的架构，不能由应用为 arm64 推断工具也是 arm64。Intel 工具的本机兼容运行不能替代原生架构或其他设备验收；当前路径发现也不代表 Windows 媒体工具已经适配。不要自动安装 Rosetta 或第三方二进制来绕过错误。

FFmpeg 的具体许可证取决于实际构建选项，不能把任意二进制一概当成 LGPL。当前没有将本机工具复制进应用或发布附件；如以后随包分发，须先确定对应版本、架构、构建选项、第三方组件、许可证声明及匹配源码的提供方式，再修改打包配置。[FFmpeg 官方许可证说明](https://ffmpeg.org/legal.html)。

这些工具用于本地校验与抽帧，不是图片／视频 AI 供应商；它们可用不等于模型登录、额度、参考图输入或真实生成已验证。

## 数据存储

桌面数据库位于 Tauri 应用数据目录中的 `workbench.sqlite3`，使用 SQLite 事务、WAL 与 FULL 同步；浏览器使用 IndexedDB 原子事务。保存校验版本号，拒绝旧窗口覆盖已更新数据。

逻辑活动库上限为 **64 MiB**，归档项目上限为 **448 MiB**，外部备份/导入上限为 **512 MiB**；实际浏览器可用空间仍受其配额限制。上一内部快照也占用存储，文件的物理体积不等于逻辑活动库大小。

旧版 localStorage 只在新库不存在时迁移，旧数据保留为回退副本。只有完整匹配旧版未编辑模板的项目会被隐藏，并保留恢复副本；已编辑项目保留。浏览器和桌面是独立存储，可通过 JSON 备份迁移，不自动同步。

## 更新与 GitHub Actions 发布

点击底栏“检查更新”，应用读取 `https://github.com/Errorrrrr/ai-creator-workbench/releases/latest/download/latest.json`，可查看版本、发布说明及适合当前平台的下载入口，也可以手动“重新检查”或“打开发布页”。检查只在主动点击时联网。不调用 GitHub REST API，不占用匿名 API 每小时 60 次额度，也不需要用户 Token。网络失败、没有已发布更新清单或下载服务暂时拒绝请求时会显示结果，不影响本地创作。

`latest.json` 随每个版本自动生成、校验并上传，与安装包和 SHA256SUMS 同属一份 Release；只有所有附件校验完成后才公开发布。它保留版本标签、发布页、说明、日期与安装包链接，客户端仍校验稳定版本、平台架构和本仓库 HTTPS 下载路径；清单请求只允许跟随本仓库附件与 GitHub 官方附件域名的有限重定向，保留超时和 1 MiB 大小限制。清单缺失时显示未找到更新清单，不回退 GitHub API。

更新使用当前仓库 `Errorrrrr/ai-creator-workbench` 的 Releases。匿名检查要求仓库和目标 Release 公开；草稿或私有仓库不会被当作公开更新。0.6.0 起可直接“更新并重启”：下载显示进度、支持取消，校验签名及其绑定版本；保存正文、候选和灵感后锁定编辑，再安装并重启。有任务未结束或保存失败则不安装。失败可重试。0.5.0 及更早版本首次升级仍需安装 DMG；数据库位于独立应用数据目录，正常升级不额外保留旧应用。

推送已有版本 tag（如 `v0.6.0`）触发 [Release macOS 工作流](.github/workflows/release.yml)。流程先核对 tag 与所有版本文件，执行 JavaScript 检查、测试、前端构建和锁定依赖的 Rust 测试，再构建 Apple Silicon `.app` 与 `.dmg`。安装包、签名结构、架构和 SHA-256 校验通过后，才发布完整 GitHub Release。

以 v0.6.0 为例，发布附件名称为：

- `ai-creator-workbench_0.6.0_aarch64.dmg`
- `ai-creator-workbench_0.6.0_aarch64.app.zip`
- `ai-creator-workbench_0.6.0_aarch64.app.tar.gz`
- `ai-creator-workbench_0.6.0_aarch64.app.tar.gz.sig`
- `latest.json`
- `SHA256SUMS`

构建 job 只有仓库读取权限，发布 job 使用 GitHub 自带 `GITHUB_TOKEN` 的 `contents: write`，不需要在源码中放置发布 token 或自动更新签名密钥。构建 job 从 `TAURI_SIGNING_PRIVATE_KEY` Secret 读取独立的更新签名私钥，应用内只包含公钥；发布前另行验证更新包签名和绑定版本。失败的上传只会留下未公开的草稿；已经公开的版本不会被工作流覆盖。预发布与旧版本不会抢占 Latest。

具体版本步骤、手动重试、校验和当前签名边界见 [GitHub Actions 发布说明](specs/GitHub-Actions发布.md)。
